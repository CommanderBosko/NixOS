# Stale Fast-Moving Research Memories

Load this when a `reference`-type memory tagged `Volatility: fast` surfaces in context — auto-loaded from a project's `MEMORY.md` index at session start, or read directly during the conversation.

The `research` skill writes `reference`-type memories tagged with a `Volatility: fast|slow` line (see this skill's own SKILL.md, Step 7). Whenever such a memory surfaces in context and its body carries `Volatility: fast`, check its `Researched: YYYY-MM-DD` date. If that date is old enough that the topic could plausibly have drifted, proactively tell the user it looks stale before relying on it, and offer to refresh it with `/research <topic>`. Use 90 days as a reasonable default gut-check, not a fixed constant — lean shorter for a fast-changing specific like pricing or a version number, longer for something that drifts more slowly even within a "fast" topic. Do **not** do this for memories tagged `Volatility: slow` (settled topics — e.g. history, definitions) no matter how old they are, and don't do it for non-research memories that carry no `Volatility` tag at all — this rule only applies to memories the `research` skill itself marked fast-moving.
